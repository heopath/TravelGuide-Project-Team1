# All My Trips Database

PostgreSQL 16 이상과 UTF-8을 사용하는 로컬 개발 DB 구성 안내서다. `pgvector/pgvector:pg16` 이미지를 기준으로 하며 운영 마이그레이션과 합성 seed를 분리한다.

## 1. 데이터베이스 생성

저장소 루트에서 PostgreSQL 관리 DB에 연결해 초기화 SQL을 실행한다.

```bash
psql -U postgres -d postgres -f database/init/create_database.sql
```

`create_database.sql`은 `all_my_trips` 데이터베이스를 없을 때만 생성한 뒤 관리자 권한으로 `create_extensions.sql`을 실행한다. 이미 데이터베이스가 있다면 DB 소유자 또는 PostgreSQL 관리자 계정으로 다음 초기 설정을 한 번 수행한다.

```bash
psql -v ON_ERROR_STOP=1 -U postgres -d all_my_trips -f database/init/create_extensions.sql
psql -v ON_ERROR_STOP=1 -U postgres -d all_my_trips -c 'GRANT USAGE, CREATE ON SCHEMA public TO allmytrips;'
```

실제 마이그레이션 계정명이 다르면 `allmytrips`를 해당 계정명으로 바꾼다. 확장 생성은 V1~V7이나 통합 DDL에 포함되지 않는다. Docker Compose의 최초 볼륨 생성 시에는 `create_extensions.sql`이 관리자 초기화 스크립트로 자동 실행된다.

## 3. 실행 순서

Flyway를 사용하지 않을 때는 V1부터 V7까지 순서대로 실행한다.

```bash
psql -v ON_ERROR_STOP=1 -U allmytrips -d all_my_trips -f database/migration/V1__member_and_place.sql
psql -v ON_ERROR_STOP=1 -U allmytrips -d all_my_trips -f database/migration/V2__trip_and_itinerary.sql
psql -v ON_ERROR_STOP=1 -U allmytrips -d all_my_trips -f database/migration/V3__ai_and_recommendation.sql
psql -v ON_ERROR_STOP=1 -U allmytrips -d all_my_trips -f database/migration/V4__travel_record.sql
psql -v ON_ERROR_STOP=1 -U allmytrips -d all_my_trips -f database/migration/V5__travel_record_social.sql
psql -v ON_ERROR_STOP=1 -U allmytrips -d all_my_trips -f database/migration/V6__admin_operation.sql
psql -v ON_ERROR_STOP=1 -U allmytrips -d all_my_trips -f database/migration/V7__ticket_reservation.sql
```

seed는 FK 의존 순서를 지킨다.

```bash
psql -v ON_ERROR_STOP=1 -U allmytrips -d all_my_trips -f database/seed/local_seed_users.sql
psql -v ON_ERROR_STOP=1 -U allmytrips -d all_my_trips -f database/seed/local_seed_places.sql
psql -v ON_ERROR_STOP=1 -U allmytrips -d all_my_trips -f database/seed/local_seed_trips.sql
psql -v ON_ERROR_STOP=1 -U allmytrips -d all_my_trips -f database/seed/local_seed_ai.sql
psql -v ON_ERROR_STOP=1 -U allmytrips -d all_my_trips -f database/seed/local_seed_records.sql
psql -v ON_ERROR_STOP=1 -U allmytrips -d all_my_trips -f database/seed/local_seed_tickets.sql
psql -v ON_ERROR_STOP=1 -U allmytrips -d all_my_trips -f database/validation/validate_seed_data.sql
```

## 4. PostgreSQL 전환 기준

- 숫자 PK는 `GENERATED BY DEFAULT AS IDENTITY`를 사용한다.
- 서버 시각은 `TIMESTAMPTZ`, 구조화된 가변 데이터는 `JSONB`, IP는 `INET`을 사용한다.
- `updated_at`은 공통 trigger로 갱신한다.
- 대표 이미지와 처리 중 신고처럼 조건부 유일성이 필요한 규칙은 부분 유일 인덱스로 강제한다.
- 이메일은 `citext`로 대소문자를 구분하지 않고 유일성을 보장한다.
- RAG 임베딩은 Spring AI PGVectorStore가 관리하는 `vector_store` 인프라 테이블을 사용한다. 비즈니스 Flyway 테이블 수에는 포함하지 않는다.

## 5. 페이지 명세 반영 결과

추가한 비즈니스 테이블은 다음과 같다.

- 여행 일정 공유: `trip_share_links`
- AI 가이드 대화: `ai_chat_sessions`, `ai_chat_messages`
- 정규화 추천 결과: `recommendation_sessions`, `recommendation_results`
- 테마 여행 등록·구성: `travel_themes`, `travel_theme_styles`, `travel_theme_places`
- 티켓 옵션·날짜/시간 선택: `ticket_product_options`, `ticket_time_slots`

항공·숙소는 외부 검색 링크, 날씨는 외부 API/Redis 캐시, 예약 대기열은 Redis TTL 구조이므로 PostgreSQL 테이블을 만들지 않는다. 결제수단 원문도 저장하지 않는다.

## 6. 개발 전용 계정과 검증

`local-user1@example.invalid`부터 8번은 USER, 9~10번은 ADMIN이다. 7번은 SUSPENDED, 8번은 WITHDRAWN이다. 현재 `password_hash`에는 `REPLACE_WITH_TEAM_BCRYPT_HASH`가 들어 있으므로 교체 전에는 로그인 테스트를 하지 않는다.

`validate_seed_data.sql`의 무결성 위반 조회는 모두 0행이어야 한다. 마지막 비밀번호 조회만 BCrypt 교체 전 10행, 교체 후 0행이 정상이다.

## 7. 제한사항

- 업무지시서의 완료 여행은 4건이므로 여행당 기록 1건 규칙을 지켜 여행 기록도 4건만 생성한다.
- 행 간 규칙인 완료 여행 소유자 일치, 댓글과 답글의 동일 기록 소속 등은 Service와 validation SQL에서도 확인한다.
- seed는 빈 로컬 DB에서 한 번 실행하는 합성 데이터이며 UPSERT를 제공하지 않는다.
- 티켓·결제·발권은 실제 공급사나 PG와 연결되지 않는 Mock 구조다.
