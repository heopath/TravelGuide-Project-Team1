# 실제 장소 기반 AI RAG 연동

## 목적

AI 일정 가이드가 임의의 상호명이나 주소를 만들어 내지 않고, 카카오 로컬 REST API로 확인한 실제 장소를 근거로 추천한다.

## 처리 흐름

1. 사용자가 AI 일정 가이드에 질문한다.
2. 기존 pgvector RAG에서 저장된 실제 장소 후보를 검색한다.
3. 질문에서 지역·장소 유형을 추출해 카카오 로컬 키워드 검색을 수행한다. 여러 DAY가 있으면 각 DAY의 지역과 카페·맛집·술집·쇼핑 등 요청 유형을 각각 검색한다.
4. 검색된 장소를 `external_provider=KAKAO`, `external_place_id=카카오 장소 ID` 기준으로 `places`에 upsert한다.
5. 저장된 장소를 Cohere 임베딩으로 즉시 pgvector에 색인한다.
6. 최신 카카오 후보를 우선하고 기존 RAG 후보를 보조로 합쳐 Cohere 프롬프트에 전달한다.

`LOCAL_SEED` 테스트 장소는 사용자 추천 후보에서 제외한다. 카카오 검색·저장·색인에 실패해도 일반 AI 추천 흐름은 유지하며, 검증되지 않은 장소명·주소·인기 정보는 만들지 않도록 프롬프트에서 제한한다. 카카오의 기타 분류 장소는 DB의 허용 카테고리인 `ATTRACTION`으로 저장한다.

## 환경 변수

```text
KAKAO_REST_API_KEY=카카오_개발자_로컬_REST_API_키
```

- 지도 표시용 `KAKAO_MAPS_JAVASCRIPT_KEY`와 다르다.
- REST API 키는 서버 환경 변수에만 설정한다.
- 키 값은 Git, properties 파일, 문서, 메신저에 기록하지 않는다.

## 실행 프로필

RAG까지 포함한 로컬 실행은 다음 조합을 사용한다.

```text
local,ai,local-ai
```

로컬 PostgreSQL에서 pgvector와 `vector_store`가 준비되어 있어야 한다. 카카오 키가 없으면 외부 장소 검색만 건너뛰며 서버는 정상 실행된다.

## 검증 항목

- 카카오 응답을 `KAKAO` 장소 DTO로 변환한다.
- 동일 카카오 장소를 다시 검색해도 `places`에 중복 생성하지 않고 갱신한다.
- 새 장소를 최대 96건 단위로 Cohere 임베딩·pgvector에 색인한다.
- 같은 질문에서 최신 카카오 후보와 기존 RAG 후보를 함께 사용하되, 최신 후보를 우선한다.
- 다일 일정 질문은 한 지역의 결과가 다른 DAY 후보를 밀어내지 않도록 검색어별 후보 수를 제한한다.
- 외부 API·RAG 장애 시 AI 기본 추천 요청은 실패하지 않는다.
