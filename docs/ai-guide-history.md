# AI-07 장기 대화 이력 저장 정책

## 목적

AI 여행 가이드는 빠른 대화 맥락을 Redis에 유지하고, 로그인 사용자별 질문과 AI 응답은 PostgreSQL에 장기 보관한다. Redis의 30분 TTL이 만료되어도 같은 여행의 최근 대화 이력을 다시 읽어 OpenAI 요청 프롬프트에 반영할 수 있다.

## 저장 구조

- Redis: 사용자·여행별 최근 3턴, TTL 30분
- PostgreSQL: 기존 `ai_chat_sessions`, `ai_chat_messages` 테이블 사용
- 대화 키: `userId + tripId`
- DB에는 사용자 질문과 AI 응답만 저장한다. API 키, 인증 토큰, 비밀번호, HTTP 헤더는 저장하지 않는다.

## 동작 순서

1. AI 추천 성공 후 Redis와 DB에 질문·응답을 각각 저장한다.
2. 다음 AI 요청 시 Redis 최근 3턴을 먼저 사용한다.
3. Redis가 비어 있거나 TTL이 만료되면 같은 사용자·여행의 DB 최근 3턴을 사용한다.
4. Redis 또는 DB 저장·조회에 실패해도 OpenAI 기본 추천 요청은 계속 처리한다.
5. 대화 삭제가 필요할 때는 Redis 키와 해당 사용자의 활성 DB 세션을 함께 삭제한다.

## 보관 및 삭제 정책

- 단기 맥락은 Redis TTL 30분으로 자동 삭제한다.
- 장기 이력의 실제 보관 기간과 사용자용 삭제 화면은 별도 정책 협의 후 추가한다.
- 현재 구현의 삭제 Service는 사용자와 여행 ID를 모두 요구하므로 다른 사용자의 대화 이력에는 접근하지 않는다.

## 실행 확인

`local,ai` 프로필에서 PostgreSQL과 Redis 연결 후 같은 `tripId`로 AI 요청을 두 번 전송한다. Redis 키를 만료 또는 삭제한 뒤 다시 요청했을 때 DB에 저장된 최근 대화가 OpenAI 요청 프롬프트에 전달되는지 로그/디버깅으로 확인한다.
