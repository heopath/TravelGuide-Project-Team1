## 2. 가장 먼저 볼 것

### 2.1 PR #226에 배포를 막는 수정이 들어 있습니다

**대기열 기능은 지금 `local`과 운영에서 앱이 아예 기동되지 않습니다.**

```text
Parameter 1 of constructor in RedisBookingQueueStore required a bean of type ObjectMapper
Parameter 2 of constructor in BookingQueueService     required a bean of type ObjectMapper
APPLICATION FAILED TO START
```

`RedisBookingQueueStore`와 `BookingQueueService`가 `@RequiredArgsConstructor`로 Jackson 2의 `ObjectMapper`를 주입받는데, Spring Boot 4는 Jackson 3을 자동 구성하므로 그 빈이 없습니다.

`@Profile("!ui")` 때문에 **`ui` 프로필에서만 감춰져 있었습니다.** UI 검수로는 절대 드러나지 않고 `local`·운영에서만 터집니다.

#226을 처리하지 않으면 대기열은 배포해도 동작하지 않습니다.

### 2.2 AI 일정 수정은 화면에서 확인되지 않았습니다

[#211](https://github.com/heopath/TravelGuide-Project-Team1/issues/211)의 수정(①)은 **코드 경로 추적과 단위 테스트까지만** 확인했습니다. 실제 브라우저에서 지도 마커와 이동수단 버튼이 뜨는지는 아무도 보지 않았습니다.

확인할 때 주의할 점이 둘 있습니다.

- **반드시 새로 생성한 AI 일정으로 봅니다.** 기존에 `place_id = NULL`로 저장된 일정은 자동 복구되지 않아 증상이 그대로 재현됩니다. 이걸 모르면 "안 고쳐졌다"고 오해합니다
- 매칭 임계값이 없어 엉뚱한 장소가 선택될 수 있습니다. 마커가 뜨더라도 위치가 납득되지 않으면 그 문제입니다

## 3. 부하 테스트 결과 (1차)

VU 30 · 재고 10 · 로컬에서만 실행. 상세는 `docs/qa/booking-queue-load-test-results.md`.

| capacity | 입장 | 성공 | 소진 | 만료 | 평균 | p95 | 최대 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 2 | 30 | 10 | 20 | 0 | 21.1s | 40.8s | 42.2s |
| **5** (기본) | 30 | 10 | 20 | 0 | 7.5s | 15.0s | 15.0s |
| 10 | 30 | 10 | 20 | 0 | 3.0s | 6.0s | 6.0s |
| 20 | 30 | 10 | 20 | 0 | 1.0s | 3.0s | 3.0s |

**어느 값에서도 재고를 넘겨 팔지 않았습니다.** 매 회차 DB로 교차 확인했습니다(예약 10건 / 서로 다른 사용자 10명 / `reserved 10 = total 10`).

**기본값 5 유지를 권장합니다.** 10 이상은 p95가 6초 아래라 30명 규모에서 대기열이 거의 드러나지 않고, 2는 p95 40초로 지나칩니다.

### 수치를 읽을 때

측정값은 서버 지연이 아니라 **사용자 체감**입니다. 스크립트가 화면과 같은 3초 주기로 순번을 확인하므로 폴링 주기만큼 올림됩니다. capacity 20의 중앙값 0초와 최대 3초가 그 경계입니다. capacity와 폴링 주기는 함께 봐야 합니다.

### 아직 못 본 것

- **만료 경로** — 이번 회차는 만료 0건이라 `admission-ttl`·`processing-ttl`이 실제로 도는지 확인하지 못했습니다. v0.5.0 제한사항의 "만료된 예약 자동 정리 없음"과 맞닿습니다
- **폴링 주기의 영향**
- **더 큰 재고·VU** — `capacity=5` 권장은 30 VU·재고 10 조건에서만 뒷받침됩니다

## 4. 이번에 새로 걸린 함정

기존 목록(`docs/handover-booking-queue-load-test.md` 5절)에 더해, 이번에 실제로 막혔던 것들입니다.

### 정적 리소스는 `build/`에서 서빙됩니다

`bootRun`은 `src/`가 아니라 `build/resources/main/`을 씁니다. CSS·JS를 고치고 화면이 그대로면 이것입니다.

```bash
./gradlew processResources
```

### 오래된 도커 볼륨에는 확장이 없습니다

`uuid-ossp`·`hstore`가 없어 Flyway `V10__vector_store.sql`이 실패합니다. `docker-entrypoint-initdb.d`는 **데이터 디렉터리가 비어 있을 때만** 실행되므로, 볼륨을 만든 뒤에 `create_extensions.sql`에 추가된 확장은 반영되지 않습니다.

```bash
docker compose exec -T postgres psql -U allmytrips -d all_my_trips \
  -c 'CREATE EXTENSION IF NOT EXISTS hstore;' \
  -c 'CREATE EXTENSION IF NOT EXISTS "uuid-ossp";'
```

### 로그인도 CSRF 보호 대상입니다

`POST /api/v1/auth/login`을 토큰 없이 부르면 **403**입니다. 토큰을 먼저 받고, 인증 후 세션이 바뀌므로 다시 받아야 합니다. k6 스크립트가 이 순서를 반대로 하고 있었습니다.

### 예약은 여행 소유자만 할 수 있습니다

여러 계정으로 부하를 걸 때 **여행을 하나로 고정하면 소유자 한 명만 성공**하고 나머지는 전부 거부됩니다. `fixtures.sql`이 계정마다 여행을 만드는 이유입니다. k6는 이제 각 VU가 `GET /api/v1/trips`로 자기 여행을 찾습니다.

### 조건부 테스트는 `skipped`를 확인합니다

`BookingQueueConcurrencyTest`는 `@EnabledIfEnvironmentVariable`입니다. 환경변수 없이 돌리면 **건너뛰고도 BUILD SUCCESSFUL**입니다. 통과로 오해하기 쉽습니다.

```bash
grep -o 'tests="[0-9]*" skipped="[0-9]*"' build/test-results/test/TEST-*BookingQueueConcurrencyTest.xml
```

### `docker compose exec`에 컨테이너 경로를 넘길 때

Git Bash가 `/docker-entrypoint-initdb.d/...`를 Windows 경로로 바꿔버립니다. `-c`로 SQL을 직접 넘기거나 `MSYS_NO_PATHCONV=1`을 씁니다.

### 8080 포트는 이 PC에서 쓸 수 없습니다

Windows 예약 포트 범위에 걸려 바인딩되지 않습니다. **8090**을 씁니다.

## 5. 환경 기동 순서

```bash
# 1) 로컬 DB·Redis (운영 아님을 반드시 확인)
docker compose up -d
docker compose exec -T postgres psql -U allmytrips -d all_my_trips \
  -c "SELECT current_database(), inet_server_addr();"
#   → inet_server_addr가 비어 있으면 로컬 컨테이너입니다

# 2) 앱 — 기본 프로필이 ui라서 반드시 local로 띄웁니다
./gradlew bootRun --args='--spring.profiles.active=local --server.port=8090'

# 3) 부하 (k6 미설치 시 도커 이미지)
docker run --rm -i --add-host=host.docker.internal:host-gateway \
  -e BASE_URL=http://host.docker.internal:8090 -e VUS=30 -e SLOT_ID=1 \
  -e PASSWORD='<로컬에서 정한 비밀번호>' \
  grafana/k6 run - < load-test/booking-queue.js
```

부하 계정은 `loadtest1@example.com` ~ `loadtest30@example.com`입니다.

**비밀번호는 문서에 적지 않습니다.** 이 저장소는 공개(public)라 한 번 커밋되면 되돌리기 어렵습니다. 각자 로컬에서 `loadtest1@example.com`으로 회원가입할 때 정한 값을 쓰고, 나머지 29개 계정은 `fixtures.sql`이 1번 계정의 해시를 복사해 같은 비밀번호로 만듭니다. k6에는 `-e PASSWORD=`로 그때그때 넘깁니다.

회차 사이에는 예약을 지우고 재고를 되돌린 뒤 Redis를 비웁니다(`fixtures.sql` 5절).

## 7. 작업 규칙 (변동 없음)

- 기본 브랜치 `develop`, 배포는 `main`, PR은 `develop` 대상 **squash merge**
- 작업 브랜치 `feature/*`, `fix/*`, `chore/*`
- 주석과 커밋 메시지는 **한국어**, 접두사 `feat:` `fix:` `chore:` `docs:`
- 주석은 "무엇을"이 아니라 **"왜"** 를 적습니다
- **머지는 작성자가 직접 합니다**
- `Closes #N`으로 이슈가 자동으로 닫히지 않습니다. 직접 닫으세요
- 작업 시작 전 `git fetch`로 최신 `develop`과 열린 PR을 확인합니다
