# AI 일정 일괄 추가 QA 체크리스트

| ID | 시나리오 | 기대 결과 |
| --- | --- | --- |
| AI-BULK-01 | DAY 1 추천 카드에서 `DAY 1 일정 모두 추가` 선택 | 검증된 실제 장소만 DAY 1에 저장되고 DAY 1 탭이 즉시 갱신된다. |
| AI-BULK-02 | 이미 저장된 장소가 포함된 추천을 다시 일괄 추가 | 저장된 장소는 `추가됨`으로 보이며 중복 요청하지 않는다. |
| AI-BULK-03 | DAY 1과 DAY 2에 서로 다른 장소를 저장한 뒤 전체 보기에서 AI 카드 확인 | 각 추천 DAY의 장소만 `추가됨`으로 표시되고, 다른 DAY의 장소 때문에 상태가 섞이지 않는다. |
| AI-BULK-04 | 중간 순서의 일정(예: 0, 1, 2 중 1)을 삭제한 뒤 새 추천 장소 추가 | 새 장소가 마지막 순서로 정상 저장되며 `sort_order` 충돌이 발생하지 않는다. |
| AI-BULK-05 | 같은 DAY에 같은 실제 장소를 다른 탭 또는 연속 요청으로 저장 | 서버가 중복 저장을 막고, 화면에는 `이미 추가됨` 상태가 표시된다. |
| AI-BULK-06 | 일정 화면에서 AI로 추가한 장소를 삭제 | AI 추천 카드의 버튼이 `추가됨`에서 `일정에 추가`로 복구된다. |
| AI-BULK-07 | 일부 장소 저장 요청 실패 | 성공·이미 추가됨·실패 개수가 한 줄로 안내되고, 성공한 장소는 유지된다. |

## 자동 검증

- `ItineraryItemServiceTest`: 삭제 뒤 `MAX(sort_order) + 1` 적용과 같은 DAY의 장소 중복 요청을 검증한다.
- DB 마이그레이션 `V18__prevent_duplicate_itinerary_places.sql`: `place_id`가 있는 일정 항목에만 `(trip_day_id, place_id)` 유일 인덱스를 적용한다.
