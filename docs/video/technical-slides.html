01 · 예약 대기열

줄을 세우고 초당 인원만 들여보낸다

대기줄에 넣고 순번을 돌려줍니다
→
입장 허용초당 정해진 수만 통과시킵니다
→
처리 중결제할 동안 자리를 잡아둡니다
→
완료끝나면 줄에서 빼냅니다
-- 한 번에 실행되는 스크립트 (일부)
local admitted = redis.call('INCR', 초당카운터)
if admitted <= 초당허용수 then state = 'READY' end
redis.call('ZREMRANGEBYSCORE', 대기열, '-inf', 만료시각)

각 단계에 제한 시간을 둡니다. 결제하다 창을 닫아도 자리가 영원히 잠기지 않습니다.

01 · 예약 대기열

말로만 하지 않고 재봤습니다

k6로 대기 시간·처리량·오류율을 재고, 중복 제출에도 예약이 하나만 생기는지는 JUnit 동시성 테스트로 확인합니다.

k6 run -e VUS=50 load-test/booking-queue.js
./gradlew test --tests '*BookingQueueConcurrencyTest'

부하 수치와 정확성 검증은 서로 다른 도구로 확인합니다.

02 · 입장 코드

캡처해서 넘겨도 소용없게

원문을 저장하지 않는다

예측하기 어려운 난수 코드를 만들고 서버에는 SHA-256 해시만 저장합니다.

짧게 쓰고 바로 폐기한다

발급 후 5분이면 만료되고, 재발급하면 앞서 띄운 코드는 즉시 무효가 됩니다.

검표할 때 티켓 행을 잠그고 사용 처리해 동시 중복 입장도 막습니다.

03 · 실시간 상담

봇이 먼저 받고, 못 하면 사람에게

봇 응대 중방이 이 상태로 시작합니다
→
대기봇이 넘기거나, 답을 못 하거나, 늦으면
→
상담원 응대관리자가 가져가 이어받습니다

주고받기는 WebSocket(STOMP)으로 합니다. 새로고침하지 않아도 상대의 말이 바로 뜹니다.

봇이 스스로 "이건 사람이 봐야 한다"고 판단하면 표시를 붙여 넘깁니다. 응답이 늦어도 손님을 기다리게 두지 않고 대기로 넘어갑니다.

04 · 여행 기록

사진이 몇 장 올지 모른 채 지면을 짠다

자리를 좌표로 박아두면 3장일 때와 7장일 때 같은 지면이 나옵니다. 장수와 사진 비율을 보고 배치를 고르게 만들었습니다.

1장가로 사진이면 가로 자리, 세로면 세로 자리
3장큰 것 하나 + 작은 것 둘
6장큰 것 하나 + 다섯
7장~3×3, 넘치면 "외 N장"

첫 글자를 크게 놓고 본문이 그 옆을 감싸 흐르게 했습니다. 줄마다 시작점을 다르게 주는 방식입니다.

04 · 여행 기록

사진 한 장 때문에 저장이 통째로 막혔다

그냥 그리면

브라우저가 내보내기를 막는다

다른 도메인 사진을 캔버스에 그리면 "오염"으로 표시하고, 이미지로 뽑는 것 자체를 거부합니다. 사진 한 장 때문에 지면 전체를 저장할 수 없습니다.

허락받은 것만 그리면

못 받은 자리만 비운다

허락을 받아 불러오고, 실패한 사진은 그 자리만 빈칸으로 둡니다. 나머지는 정상적으로 저장됩니다. 왜 비었는지도 화면에 알려줍니다.

직접 만들다 부딪혀야 알 수 있는 제약이었습니다.
